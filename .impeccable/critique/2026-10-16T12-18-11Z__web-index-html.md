## 设计特异性裁决

**半-authored。** 身份锚点是真实的：粉立绘侧栏（#f7c9cd + sidebar.jpg 底部立绘）、莓果导航胶囊（#c2185b）、亚麻确认框（--linen）、带纪律的表情包系统（data-sticker 状态化 + ≥75% 内存自动退场 + onerror 降级占位）。但内容区本体（中性灰画布 + 白卡 + 橙 CTA）类别可互换，且侧栏暖粉与内容区中性冷灰之间存在温度断层。表情包只出现在低风险时刻，峰值时刻（清理完成 / 深度优化完成）缺席。

## 整体印象

这是一份「个性已立、结构未闭」的中期稿：删除类产品最难的渐进披露（扫描/清理两步分离、清理按钮扫描后才出现）做对了，禁用即解释文化真正落地了，但两个高风险面（gaming 页 116 项注册表写入、删除方式默认不可逆）反而缺乏与其风险相称的防护与强调——重保倒挂。探测器（Assessment B）29 条 finding 里，真正的代码级缺陷几乎为零：warning 绝大多数是 spec 自证的身份配对（橙 CTA 白字）、opacity 合成的禁用态、表情包 alt 占位文字、Inter 字族——**都是假阳性**。真正的信号收敛到两点：DESIGN.md 与 shipped 界面脱节（所有 design-system 告警的根），以及 --body-mid #75716a 在灰底上 4.3–4.4:1 的临界对比度。

## What's Working

1. **扫描/清理两步分离 + 渐进披露**：`#junk-clean` 扫描后才出现、`#junk-apply` 先行——删除类产品的教科书级风险闸门，PRODUCT 原则「宁可少清」的 UI 化。
2. **禁用即解释文化**：待机行禁用时文案整句替换（`memory.js applyCapabilities`）、「还原系统设置」禁用带 title——把「为什么不能点」写进界面而非埋进日志。
3. **表情包系统的克制纪律**：状态化、内存紧张时主动退场、缺图降级为中性占位块——个性带规则，没有沦为贴纸堆砌。

## Priority Issues

**P1 — DESIGN.md 与 shipped 界面脱节** `document`
- What：spec 仍写暖米 #fffefb / 无投影 / 12px 圆角 / 橙为唯一彩；shipped 是中性灰 #f5f5f4 + 白卡 + --shadow-1 投影 + 8px + 莓果胶囊 + 绿授权钮 + 徽章梯度。B 的 6 条 design-system-color + 2 条 radius 告警全部源于此。
- Why：spec 是下一个 agent 的「真相来源」。脱节意味着任何后续 agent 都会按旧 spec「修回」暖米无投影，毁掉用户已选定的柔化方向。
- Fix：把柔化方向写成规范正文（更新 frontmatter 令牌、§6 投影段改为「白卡允许 --shadow-1」、§2 增补莓果/绿/亚麻/banner-tint、radius md 8px），使 tokens.css 与 DESIGN.md 逐令牌对齐。

**P1 — gaming 页扳动即写注册表，无防护** `harden`
- What：`gaming.js:194-200` 直接 `gaming_apply`，含「安全」分组；无确认、无 diff、无批量、无撤销。
- Why：这是全应用风险最高的页面（116 项、写 HKLM、含 HAGS/安全/系统服务），重保却最少——与「宁可少清」的品牌承诺倒挂。Alex 用户不会逐个核对 116 项。
- Fix：危险分组（安全/系统服务/HKLM）加确认；行内「当前值 → 将改为」预览；页级批量应用推荐值/批量还原；写前备份已存在但需在 UI 暴露「已备份，可还原」。

**P1 — .badge-ok 与 .badge-mute 语义坍缩** `clarify`
- What：`app.css:236-239` 两者仅 500 vs 400 字重之差，进程列表「可整理」与「受保护」两颗几乎一样的灰药丸。
- Why：删除工具的核心语义对（可动 vs 不可动）视觉上无法区分，用户扫列表时无法一眼识别哪些进程安全。
- Fix：受保护（.badge-mute）改墨描边语言（1px ink 边 + canvas 底），与「可整理」的实心灰区分开。

**P2 — 内存页 IA 超载 + 双一键加速入口** `distill`
- What：首屏 = 游戏优先级卡 + 电源计划卡 + 6 开关卡 + 深度折叠 + 215 行进程列表 + 底栏 3 按钮；一键加速有 `#mem-boost`（卡内）与 `#action-primary`（底栏）两个入口。
- Why：认知负荷「单一焦点」失败；双入口制造犹豫。且「游戏优先级」首选项是 msedge.exe（全部窗口进程），标题承诺游戏数据却是全部窗口进程。
- Fix：电源计划移去 gaming 页；「游戏优先级」更名「程序优先级」或如实说明范围；卡内 `#mem-boost` 降级，底栏橙钮为唯一主 CTA。

**P2 — 删除方式默认不可逆，确认框不复述模式** `clarify`
- What：不可逆是默认态，但 `junk.js:316` 确认框只说条数+大小，不复述「直接删除，无法恢复」；delmode 行的「☐ 移入回收站 …删掉就找不回来了」语义读反。
- Why：Riley 压力用户在高风险时刻看不到模式提醒；「可还原」态加了 .warn 墨色强调，不可逆默认态反而无强调——强调方向反了。
- Fix：确认文案按模式分支（直接删除时明确「无法恢复」、按钮文案说「直接删除」）；或默认勾选移入回收站，把不可逆变成主动选择。
